# Cross-source Hard-Augmentation Pipeline

This pipeline synthesises **HARD multimodal algorithmic problems** (class-Solution
LeetCode style) by drawing inspiration from a **mixed pool** of:

* `leetcode_native` — clean class-Solution problems with images
* `leetcode_newgen` — previously-synthesised LeetCode-style problems
* `codeforces_solved / atcoder_solved / aizu_solved` — competitive STDIN/STDOUT
* `mmcode_full` — competitive STDIN/STDOUT with images

Only the LC sources are used as **direct ICL examples** (output-style consistency).
The competitive sources are surfaced into a separate **inspiration pool** — their
images and prose are shown to the LLM without solutions, to nudge generations
toward harder algorithmic content (network flow, segment trees, suffix array,
geometric algorithms, etc.).

The output schema is identical to `competition-pipeline/newgen-pipeline/`: each
problem is a parametric Python module rendering a deterministic image and
producing test cases for sandbox verification.

## Folder layout

```
cross-aug-pipeline/
├── README.md
├── requirements.txt
├── run_pipeline.sh                 — end-to-end orchestrator
├── seeds_sample/                   — small subsamples of each upstream source
│   ├── leetcode_native_records.jsonl   (20 Hard+Medium)
│   ├── leetcode_newgen_records.jsonl   (20 Hard)
│   ├── mmcode_full_records.jsonl       (20 Hard subset)
│   ├── competition_solved/             (CF / AC / Aizu × 8 each)
│   │   ├── codeforces_solved.jsonl
│   │   ├── atcoder_solved.jsonl
│   │   ├── aizu_solved.jsonl
│   │   └── images/
│   └── images/                          (LC + MMCode-Full first images)
├── extract_ingredients.py          — algo / struct / domain / difficulty pools
├── ingredients.json                 (generated by extract_ingredients)
├── build_seeds.py                  — copy first images, write ICL + inspiration
├── prompts.py                      — system / user prompt builders
├── generate_templates.py           — async LLM call → templates/<id>.py
├── run_templates.py                — variant render + sandbox verification
├── audit_leakage.py                — Jaccard similarity vs upstream pool
├── build_sft.py                    — wrap into SFT records (comments stripped)
├── recover_failed.py               — re-run validators on quarantined templates
└── llm_client.py / logger.py / sandbox.py
```

## Quick start

```bash
export OPENAI_BASE_URL="https://your-gateway/v1"
export OPENAI_API_KEY="sk-..."
pip install -r requirements.txt
./run_pipeline.sh                # smoke run: ~24 SFT records on the seeds_sample
```

This runs the whole pipeline end-to-end:

1. `extract_ingredients.py` — write `ingredients.json` (advanced algo / struct
   tags, six visual aspects, hard-biased difficulty mix 5/25/70).
2. `build_seeds.py` — pull seeds from `seeds_sample/` (overridable via env vars,
   see below) and emit `seeds/icl_records.jsonl` + `seeds/inspiration_records.jsonl`.
3. `generate_templates.py` — sample a recipe + 3 ICL examples + 1 optional
   inspiration image and ask the LLM to write a parametric template.  Templates
   that don't compile or are missing required symbols are quarantined to
   `failed_templates/`.
4. `run_templates.py` — render each template into N concrete variants, drive
   them through the in-process sandbox, and keep only those with 100% test
   pass.
5. `audit_leakage.py` — compute token-level Jaccard against the local upstream
   pool (or override with env vars) and reject high-similarity items.
6. `build_sft.py` — wrap surviving variants into SFT records (`sft/train.sft.clean.jsonl`).

## Pointing at your own upstream corpus

`build_seeds.py` and `audit_leakage.py` honour env vars that override the
default `seeds_sample/` paths, so you can re-target the pipeline at your full
corpus without code edits:

```bash
export CROSS_AUG_LC_NATIVE=/path/to/leetcode_records.jsonl
export CROSS_AUG_LC_NEWGEN=/path/to/leetcode_newgen.jsonl
export CROSS_AUG_COMP_DIR=/path/to/comp_solved/        # contains *_solved.jsonl + images/
export CROSS_AUG_MMCODE_FULL=/path/to/mmcode_full_records.jsonl

# audit pool — colon-separated jsonls
export CROSS_AUG_AUDIT_SOURCES="$CROSS_AUG_LC_NATIVE:$CROSS_AUG_LC_NEWGEN:$CROSS_AUG_MMCODE_FULL"

python build_seeds.py     # rebuild seeds from your corpus
python audit_leakage.py   # audit against your full pool
```

## Cost & throughput

For a full run on a real corpus (target=500 templates × 5 variants), Claude-4.6
spending was ~$50 over ~75 minutes at 32-way concurrency.  The smoke run
exercising `seeds_sample/` lands in single-digit dollars and finishes in
~10 minutes.

## Output schema

Each surviving SFT record is a JSON object with at minimum:

```jsonc
{
  "id":          "cross_aug_000001_v0",
  "parent_qid":  "cross_aug_000001",
  "title":       "...",
  "method_name": "minCoverCost",
  "function_signature": "def minCoverCost(self, ...) -> int",
  "difficulty":  "Hard",
  "image":       "images/cross_aug_000001_v0_0.png",
  "images":      ["images/cross_aug_000001_v0_0.png", "images/cross_aug_000001_v0_1.png"],
  "query":       "<image>\n\n# Title\n\nDescription with __INPUT_K__/__OUTPUT_K__ ...",
  "code":        "class Solution:\n    def minCoverCost(...): ...",
  "response":    "```python\nclass Solution:\n    def minCoverCost(...): ...\n```",
  "test_cases":  [...],          // sandbox-verified
  "n_test_cases": 10,
  "algo_tags":   ["Tree DP", "Segment Tree (Lazy / Persistent)"],
  "visual_aspect": "tree-diagram (rooted, labeled nodes, possibly weighted edges)",
  "icl_qids":    [...],
  "leakage_audit": {"title_sim": 0.21, "desc_sim": 0.13}
}
```
